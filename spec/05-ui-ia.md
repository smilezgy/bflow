# Bflow —— 交互与信息架构

> 设计目标：把「渠道能力不可信」这一核心事实**显性化**到界面上。
> 用户随时知道自己选了什么、上游实际给了什么、偏差在哪。

---

## 1. 信息架构总览

```
Bflow
├── 工作台（默认落地页）
│   ├── 快速生成卡片（提示词 → 出图）
│   ├── 最近产物
│   └── 最近任务
├── 画布（Canvas）★ 核心
│   ├── 无限画布
│   ├── 节点：图像 / 文本 / 视频 / 分组
│   └── 右侧属性面板
├── 素材库（Library）
│   ├── 网格 / 列表视图
│   ├── 分类、标签、搜索
│   └── 批量操作
├── 任务中心（Tasks）
│   ├── 进行中 / 成功 / 失败
│   └── 偏差警告汇总
├── 渠道（Channels）★
│   ├── 渠道列表
│   ├── 能力表查看 / 手动覆盖
│   └── 实时验证
├── 设置（Settings）
│   ├── 存储位置
│   ├── 主题 / 语言
│   └── 更新
└── 对话（Chat）
    └── 用自然语言驱动生成与编辑
```

★ 标记为本项目相对同类工具的重点差异化区域。

---

## 2. 全局设计原则

| 原则 | 说明 | 依据 |
|---|---|---|
| **实际 vs 请求始终可对照** | 任何产物都同时显示「你选的」与「实际得到的」 | P0：渠道普遍不 honor 请求 |
| **偏差用警告色，不用错误色** | 产物有效，只是与预期不同 | 同上 |
| **能力表可见** | 用户能查某渠道支持什么、实测于何时 | 能力会变 |
| **不自动降级** | 系统不替用户改参数 | 用户明确要求 |
| **长任务不阻塞** | 异步执行，进度可见，可取消 | 上游耗时 30s~15min |

## 3. 关键界面：快速生成

### 3.1 布局

```
┌─────────────────────────────────────────────────────────────┐
│  Bflow        [工作台] [画布] [素材库] [任务] [渠道] [设置]  │
├─────────────────────────────────────────────────────────────┤
│ ┌─────────────────────────────────┐ ┌─────────────────────┐ │
│ │ 提示词                          │ │  预览                │ │
│ │ ┌─────────────────────────────┐ │ │ ┌─────────────────┐ │ │
│ │ │ a red apple on a wooden...  │ │ │ │                 │ │ │
│ │ └─────────────────────────────┘ │ │ │    (图像)        │ │ │
│ │                                 │ │ │                 │ │ │
│ │ 参考图  [+ 添加]  (缩略图条)     │ │ └─────────────────┘ │ │
│ └─────────────────────────────────┘ │                     │ │
│ ┌─────────────────────────────────┐ │  ⚠️ 格式偏差提示     │ │
│ │ 渠道 ▾  模型 ▾  尺寸 ▾          │ │                     │ │
│ │ 格式 ▾  质量 ▾  复杂度 ▾        │ │  [下载] [存入素材库] │ │
│ │ 背景 ▾  压缩 ▾                   │ │  [加入画布]          │ │
│ └─────────────────────────────────┘ └─────────────────────┘ │
│                                    [ 生成 ]                 │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 选项的动态性

**选项列表由渠道能力表驱动**，不可用的选项不显示（而非显示后报错）。

以「格式」下拉为例，CH-A：

```
✓ PNG
✓ JPEG
✓ WebP
✓ SVG
✓ GIF
```

CH-C（格式不 honor 的渠道）：

```
✓ PNG     ← 实际会返回 WebP，鼠标悬停有说明
✓ JPEG
✓ WebP
✓ SVG
✓ GIF
```

> **CH-C 的处理**：因为 `honors_request: false`，选项旁显示一个 ⚠️ 标记，
> 悬停提示「该渠道不保证按所选格式出图」。用户仍可选 —— 选了就选，
> 出了偏差再如实提示。这是「不降级、不隐瞒」原则的体现。

**联动规则**：

| 触发 | 联动 |
|---|---|
| 选 `background=transparent` | 格式若为 JPEG → 提示「JPEG 不支持透明背景」并提供切换为 PNG/WebP |
| 选 `output_format=png` | 压缩选项置灰（PNG 忽略压缩率）|
| 选 `output_format=jpeg/webp` | 压缩选项启用 |
| 选 `output_format=gif` | 追加「帧数」「帧时长」选项 |
| 选 `output_format=svg` | 数量锁定为 1，并提示「SVG 仅支持单张」|
| 渠道切换 | 重新按新渠道能力刷新所有选项 |

### 3.3 偏差提示（核心差异化）

出图完成且实际格式/尺寸与请求不符时，在预览区下方显示**琥珀色**提示条：

```
┌──────────────────────────────────────────────────────────┐
│ ⚠️ 你选择了 SVG 格式，但上游实际返回的是 PNG。            │
│    产物已按上游实际结果交付。如需 SVG，请换一个支持该    │
│    格式的渠道。                          [了解更多] [×]  │
└──────────────────────────────────────────────────────────┘
```

尺寸偏差同理：

```
⚠️ 你请求了 256x256，该渠道输出为 1024x1024。
```

**多条偏差合并显示**，用分隔号隔开。

### 3.4 生成失败

失败用**红色**提示，且明确区分是否已计费：

```
┌──────────────────────────────────────────────────────────┐
│ ✕ 生成失败                                                │
│   该渠道不支持 SVG 输出格式。                              │
│   建议：① 把输出格式改成 PNG；② 或换一个支持该格式的渠道。│
│                                          [重试] [×]      │
└──────────────────────────────────────────────────────────┘
```

## 4. 关键界面：渠道管理 ★

### 4.1 渠道列表

```
┌──────────────────────────────────────────────────────────────────────┐
│ 渠道                                          [新增渠道] [刷新能力] │
├────────┬──────────┬────────┬───────────────┬─────────────────────────┤
│ 代号   │ 协议     │ 模型   │ 能力状态      │ 最近实测               │
├────────┼──────────┼────────┼───────────────┼─────────────────────────┤
│ CH-A   │ OpenAI   │ 2.6-*  │ ✅ 完整支持   │ 2 小时前 · 实测          │
│ CH-B   │ OpenAI   │ 2.6-*  │ ⚠️ 部分格式   │ 2 小时前 · 实测          │
│        │          │        │   被忽略      │                         │
│ CH-C   │ OpenAI   │ 2.6-*  │ ⚠️ 格式不保证 │ 2 小时前 · 实测          │
│ CH-D   │ OpenAI   │ —      │ ❌ 无通道     │ 5 小时前 · 实测          │
└────────┴──────────┴────────┴───────────────┴─────────────────────────┘
```

**关键**：列表只显示**代号**（CH-A、CH-B），不显示渠道真实名称/域名。
用户自己配置的渠道除外（那是用户自己的东西）。

### 4.2 渠道详情：能力表

```
┌─────────────────────────────────────────────────────────────┐
│ CH-B                                       [验证] [编辑能力] │
├─────────────────────────────────────────────────────────────┤
│ 协议      OpenAI Images                                    │
│ 地址      https://••••••••••••••••••••••                     │  ← 域名打码
│ 密钥      sk-••••••••••••                                  │
├─────────────────────────────────────────────────────────────┤
│ 输出格式                                                     │
│   PNG      ✅  正常返回                                      │
│   JPEG     ✅  正常返回                                      │
│   WebP     ⚠️  被静默忽略，实际按 PNG 返回                    │
│   SVG      ⚠️  被静默忽略，实际按 PNG 返回                    │
│   GIF      ❌  拒绝：拼版超出平台像素预算                     │
├─────────────────────────────────────────────────────────────┤
│ 尺寸策略     越界即报错（reject）                             │
│ 尺寸区间     655,360 ～ 8,294,400 像素 · 长边 ≤ 3,840         │
│ 质量档       auto/low/medium/high/xhigh/max                 │
│ 复杂度       auto/low/medium/high                            │
│ 编辑链路     ✅ 支持 · 参考图上限 4 张                         │
├─────────────────────────────────────────────────────────────┤
│ 最近实测     2026-11-16 18:18                                │
│ 能力来源     实测（probe）  [切换为手动]                       │
└─────────────────────────────────────────────────────────────┘
```

**「编辑能力」**：用户可覆盖实测值（P0 结论：能力变化比复测快）。
覆盖后 `能力来源` 变为 `手动`，并显示「此值由你设置，未经实测验证」。

**「验证」**：发一次真实请求刷新能力表，消耗一次额度，需二次确认。

### 4.3 新增渠道

分步向导：

```
① 基本信息   代号 / 显示名 / 协议 / 地址 / 密钥
② 模型       从渠道拉取模型列表（GET /models），或手填
③ 能力验证   可选：跑一次标准探测（约 8 次请求，可能计费）
             ⚠️ 将发起 8 次真实请求，可能产生费用
④ 完成       显示能力摘要
```

### 5.1 布局

```
┌────────────────────────────────────────────────────────────┐
│ 工具栏: [选择][手型][图片][文本][视频][分组] ... [缩放][网格]│
├────────────────────────────────────────────────────────────┤
│                                                            │
│         ┌────────┐        ┌────────┐                     │
│         │ 图像节点 │──连线──▶│ 图像节点 │                    │
│         │ 1024²   │        │ + 局部编辑│                   │
│         └────────┘        └────────┘                     │
│                    (无限画布)                              │
├────────────────────────────────────────────────────────────┤
│ 右侧属性面板（选中节点时）                                   │
│  提示词 / 渠道 / 模型 / 格式 / 尺寸 / 质量 / 复杂度         │

```

### 5.2 节点上的偏差标记

若节点图像是「格式/尺寸与请求不符」的产物，节点角标显示 ⚠️，
悬停显示具体偏差。**不遮挡图像本身**。

### 5.3 局部编辑（mask）

选中图像节点 → 「局部编辑」→ 在图上涂抹遮罩 → 输入指令 → 生成。
遮罩作为独立资源上传（`purpose=mask`），与主图一起提交。

## 8. 状态与反馈规范

### 8.1 反馈层级

| 层级 | 用于 | 样式 | 时长 |
|---|---|---|---|
| **阻断** | 生成失败、无法继续 | 红色浮层，含错误码与建议 | 需手动关闭 |
| **警告** | 格式/尺寸偏差、渠道能力过期 | 琥珀色浮层 | 12 秒自动消失 |
| **提示** | 降级了可安全参数、保存成功 | 灰色浮层 | 7 秒自动消失 |
| **行内** | 字段级校验 | 输入框下方红字 | 常驻直到修正 |

### 8.2 加载态

| 场景 | 表现 |
|---|---|
| 生成中 | 预览区骨架屏 + 已过秒数 + 可取消按钮 |
| 任务排队 | 任务中心置顶显示「排队中」|
| 渠道验证中 | 能力表区域加载条 + 逐项点亮 |
| 批量操作 | 顶部进度条 + 逐项结果 |

### 8.3 错误码到文案的映射

前端**必须**对未知错误码优雅降级（展示服务端 `message`，不崩溃）。
客户端不硬编码错误码文案，文案由服务端 `message` + `hint` 下发 ——
这样新增错误码无需发版。

## 9. 响应式与平台

| 断点 | 布局 |
|---|---|
| ≥ 1440px | 画布 + 常驻右侧属性面板 |
| 1024–1440px | 右侧面板改为抽屉 |
| < 1024px | 单列堆叠；画布为主要视图，属性面板为底部抽屉 |

**桌面优先**：生图与画布创作是桌面场景，移动端只保证「查看 + 轻量生成」。

## 11. 关键用户旅程

### 旅程 A：首次使用

```
落地工作台 → 引导添加渠道（向导）→ 选模型 → 跑一次验证
→ 能力表生成 → 进入快速生成 → 出图 → 存入素材库
```

### 旅程 B：产出 SVG（遇渠道不支持）

```
快速生成 → 选 SVG → 提交 → 渠道返回 400
→ 红色阻断提示「渠道不支持 SVG」+ 建议「改用 PNG 或换渠道」
→ 用户点建议 → 格式切 PNG → 重新生成 → 成功
```

### 旅程 C：产出格式与请求不符

```
快速生成 → 选 SVG → 提交 → 200，返回 PNG
→ 琥珀色警告「你选了 SVG，实际返回 PNG，产物已交付」
→ 预览显示 PNG 图（正常可用）
→ 用户可下载，或换渠道重试
```

### 旅程 D：画布创作

```
画布 → 添加图像节点 → 填提示词 → 生成 → 节点出现
→ 选中节点 → 属性面板改提示词 → 重新生成 → 节点原地更新
→ 选中两个节点 → 连线 → 以 A 为参考图编辑 B
```

### 旅程 E：发现渠道能力过期

```
渠道页 → CH-D 显示「最近实测 35 天前」
→ 橙色徽章「能力数据已过期」
→ 点「验证」→ 二次确认（会发起请求，可能计费）
→ 验证完成 → 能力表刷新
```

## 12. 与 P0 结论的对应

| 界面设计 | 来自哪条实测结论 |
|---|---|
| §3.2 选项由能力表驱动 | 渠道支持度差异大且会变 |
| §3.2 CH-C 的 ⚠️ 标记 | `honors_request: false` 需前置告知 |
| §3.3 琥珀色偏差提示 | 格式/尺寸偏差普遍存在且产物有效 |
| §3.4 失败用红色 + 区分是否计费 | 上游 200 即计费 |
| §4.1 列表只显示代号 | 公开项目不暴露渠道来源 |
| §4.2 地址打码 | 同上 |
| §4.2 「编辑能力」人工覆盖 | 能力变化快于复测频率 |
| §4.3 验证前二次确认 | 探测会产生真实费用 |
| §6 偏差列 | 需一眼看出哪些产物与请求不符 |
| §8.1 反馈四层级 | 偏差≠失败，需视觉区分 |
| §8.3 错误文案服务端下发 | 错误码会新增，客户端不硬编码 |
